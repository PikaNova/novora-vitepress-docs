# 管理账号与角色

账号体系的目的是让每个人只做自己该做的事，并且每件事都能追溯到人。本篇给出三种最常用的建账号方式。

## 先想清楚三件事

创建任何账号之前，先确定：

1. **角色**——他能操作哪些模块（超级管理员 / 年级管理员 / 班级管理员 / 班级访客 / 自定义角色）；
2. **数据范围**——他能看到哪些年级或班级；
3. **交付方式**——初始密码怎么安全地交给他。

角色决定「能做什么」，数据范围决定「对谁做」，两者必须同时满足。只给模块权限不给范围，他什么也看不到；只给范围不给权限，他只能看不能改。

## 方式一：单个创建（最常用）

1. 进入「用户与权限」；
2. 点击新建用户；
3. 填写登录用户名（3–40 位字母、数字、点、横线或下划线）；
4. 填写显示名称（可用中文）；
5. 设置初始密码（至少 8 位）；
6. 选择角色；
7. 选择数据范围：全校、指定年级，或额外指定班级；
8. 保存并把凭据安全交付给对方。

## 方式二：一班一账号批量创建

适合给所有班级配班级管理员：

1. 点击「批量添加班级管理员」；
2. 设置用户名统一前缀（例如 `class-`）；
3. 设置初始密码；
4. 用班级选择器勾选目标班级；
5. **确认创建数量**；
6. 保存后分别交付每个账号。

每个账号自动只获得对应班级的作用域。年级管理员只能在自己的授权年级内批量创建，越权范围会被服务端拒绝。

::: tip 首次登录会强制改凭据
批量创建的班级管理员首次登录时，必须同时设置自己的新用户名和新密码。两项一次性保存，成功后旧会话立即失效。
:::

## 方式三：自定义角色

内置的四种角色覆盖大多数情况。需要更细的划分时再建自定义角色：

1. 先写清这个角色要做什么（一句话）；
2. 为每个模块选择访问级别：

   | 级别 | 含义 |
   | --- | --- |
   | 不可访问 | 菜单不显示，接口也拒绝 |
   | 仅查看 | 能看不能改 |
   | 可管理 | 能看也能改 |

3. 保存角色，再在创建用户时选用。

常见配方：

| 场景 | 角色配置 |
| --- | --- |
| 高一只读教务 | 只读大型考试、周测、学校结构；范围高一 |
| 只维护周测的教务 | 可管理周测；只读大型考试；范围指定年级 |
| 只看看板的电教老师 | 只读设备管理；范围全校 |

不要为了省事授予全部权限。数据库重置、初始化、角色管理、部署和超级管理员相关操作始终只保留给超级管理员。

## 密码重置和找回

| 忘记密码的账号 | 可处理人员 |
| --- | --- |
| 班级管理员 | 所属年级管理员或超级管理员 |
| 年级管理员 | 超级管理员 |
| 超级管理员 | 其他超级管理员，或使用恢复密钥 |

重置时可以自动生成 14 位临时密码，也可以手动设置。临时密码**只展示一次**，关闭前必须安全交付；重置后旧会话立即失效，对方下次登录会被要求更新凭据。

## 人员变动时的处理

| 情况 | 建议动作 |
| --- | --- |
| 离职、调岗 | **停用**账号，不要删除 |
| 换年级 | 修改数据范围，不要新建账号 |
| 职责扩大 | 调整角色或范围 |
| 多人共用一个账号 | 拆成独立账号，共用无法追溯 |

停用比删除更适合人员变动：审计日志中保留的历史记录仍有对照。

## 邮箱验证码登录（可选）

在系统设置中配置 SMTP 后，管理员可以在「我的账户」绑定邮箱，之后可以改用「邮箱 + 6 位验证码」登录。

限制：同一邮箱 60 秒内只能发送一次，同一 IP 每小时有次数限制，验证码 5 分钟内有效且只能用一次。邮箱登录不会自动创建账号，只允许绑定到已有管理员账号的邮箱。

## 定期检查

建议每学期至少检查一次：

- [ ] 超级管理员是否保持最少必要人数；
- [ ] 是否有已离职人员仍能登录；
- [ ] 年级和班级授权范围是否仍然符合职责；
- [ ] 是否有账号共享的情况；
- [ ] 审计日志中有没有异常的重置或删除。
