# 部署完的第一个小时

系统能打开了，但还不算能用。这一页按顺序给你部署后的第一小时清单。

## 第 1 步：完成初始化（约 15 分钟）

如果还没做，先走完初始化向导：

1. 学校信息（省份、校名）；
2. 年级和班级；
3. 学期开始日期、周次模式、节假日规则、默认运行模式；
4. 确认配置；
5. 查看使用文档（可跳过）；
6. 修改超级管理员密码；
7. 保存只显示一次的恢复密钥。

::: warning 恢复密钥必须存好
数据库只保存它的哈希，系统之后无法再次显示原文。忘掉就只能靠其他超级管理员重置。
:::

## 第 2 步：确认数据真的写进去了（约 5 分钟）

1. 在后台新建一场测试考试；
2. 刷新页面，确认它还在；
3. 打开[运行总览](/features/02-overview-module)，确认「数据库状态」正常；
4. 测完删掉这场测试考试。

这一步是排除「页面能打开但数据库没连上」的情况。

## 第 3 步：让一台教室大屏跑起来（约 10 分钟）

1. 在教室设备上打开你的 Novora 地址；
2. 在首页选择这台设备实际所属的年级和班级；
3. 进入考试大屏；
4. 大屏静置 1 分钟后会出现「建议全屏」提示条，点一次进入全屏；
5. 回到后台[设备管理](/features/06-devices-module)，确认这台设备显示在线且绑定正确。

一台设备只绑定一个班级。绑定关系存在云端，清除浏览器缓存后需要重新选一次。

## 第 4 步：创建账号并分工（约 15 分钟）

不要所有人共用超级管理员账号。按职责建：

| 谁来维护什么 | 给他什么角色 |
| --- | --- |
| 全校系统负责人 | 超级管理员（保持最少人数） |
| 各年级教务 | 年级管理员 |
| 班主任或班干部 | 班级管理员（可用「一班一账号」批量建） |
| 巡考、教务查看 | 班级访客（只读） |

创建入口与规则见[用户与权限](/features/07-users-module)。批量创建的班级管理员首次登录必须同时设置自己的新用户名和新密码。

## 第 5 步：试着安排一场真实考试（约 15 分钟）

用一场即将到来的考试走完整流程，比看文档更容易发现问题：

1. 在[大型考试](/features/08-create-major-exam)里创建考试容器并选好适用范围；
2. 逐科添加分科目和起止时间；
3. 打开「预览与导出 PDF」，检查校名、年级和各科时间；
4. 在目标班级的大屏上确认显示正确；
5. 换一个非目标班级，确认**不会**误显示；
6. 回到[运行总览](/features/02-overview-module)确认没有新增冲突提醒。

V2.8.0 起，考试当天还可以在考试记录里开考、暂停、继续、延长和结束，所有操作都会留下记录。

## 第 6 步：把维护规则定下来（约 10 分钟）

现在做，比出事之后补要省事：

- [ ] 指定 GitHub / Vercel / Neon（或服务器）的责任人；
- [ ] 做一次数据库备份，并**演练一次恢复**；
- [ ] 记录当前版本号和提交号；
- [ ] 确认恢复密钥仍在可取的受控位置；
- [ ] 决定遥测与诊断日志是否开启。

云端备份与更新：[Vercel 日常维护](/guide/vercel/09-maintenance)。本地备份与更新：[更新与维护](/guide/local/06-maintenance)。
