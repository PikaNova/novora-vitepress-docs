# 假期与开学

长假是系统最容易"放坏"的时间段：服务器被断电、域名欠费、设备被搬动、老师忘了操作方式。这篇给出放假前和开学前的固定动作。

## 放假前一周

### 数据

- [ ] 归档本学期已完成的大型考试；
- [ ] 导出需要长期保存的考试与周测 JSON；
- [ ] 完成一次完整数据库备份；
- [ ] 把备份拷贝到离线介质或网络存储；
- [ ] 记录当前版本号和提交号。

### 结构

- [ ] 确认下学期是否需要新建年级或调整班级；
- [ ] 记录需要升级的年级归属变化；
- [ ] 清理明显不再需要的测试数据（谨慎操作，先备份）。

### 人员

- [ ] 停用已离职人员的账号；
- [ ] 确认假期期间的值班联系人；
- [ ] 交接维护责任（如果负责人休假）。

## 放假前最后一次检查

| 项目 | 云端 | 本地 |
| --- | --- | --- |
| 服务可用性 | 确认 Vercel 项目与域名正常 | 确认容器/服务设置了开机自启 |
| 数据库 | 确认 Neon 项目不会因闲置被回收 | 确认数据卷存在且空间充足 |
| 费用 | 检查域名、平台额度和付款方式 | 无 |
| 电源 | 无 | 确认机房不断电，或知道如何恢复 |
| 证书 | Vercel 自动续期 | 确认反向代理证书自动续期正常 |

::: warning 假期欠费是很常见的故障
域名到期、平台额度耗尽、信用卡过期都会让系统在假期静默下线。放假前专门检查一次付款方式。
:::

## 设备处置

教室电脑有两种处理方式，选一种并**告诉所有人**：

| 方式 | 做法 | 风险 |
| --- | --- | --- |
| 保持通电 | 设备继续运行，大屏照常 | 耗电，但开学零操作 |
| 断电收存 | 关机并记录存放位置 | 开学需要逐台重新开机并打开大屏 |

如果选择断电：

- 记录每台设备的教室和实例 ID 对应关系；
- 提醒不要清除浏览器数据（会丢失班级绑定）；
- 开学时按记录逐台恢复。

## 开学前两周

### 系统侧

- [ ] 更新到目标稳定版并完成验收（[Vercel 维护](/guide/vercel/09-maintenance) / [本地维护](/guide/local/06-maintenance)）
- [ ] 更新学期开始日期；
- [ ] 确认周次模式（统一周表 / A/B 周）；
- [ ] 确认节假日排除规则；
- [ ] 确认默认运行模式；
- [ ] 新建或调整年级、班级；
- [ ] 调整年级管理员的授权范围；
- [ ] 恢复密钥位置确认可取用。

### 数据侧

- [ ] 检查各班周测计划的生效日期是否已更新到新学期；
- [ ] 确认 A/B 周起始周次与学校安排一致；
- [ ] 为新班级创建班级管理员账号；
- [ ] 从备份恢复一次到测试库，验证备份可用（至少每学年做一次）。

## 开学前一周

- [ ] 逐台恢复教室设备：开机、打开地址、选择班级、进入全屏；
- [ ] 后台确认所有设备在线且绑定正确；
- [ ] ClassIsland 插件确认同步正常，必要时重新配对；
- [ ] 用一台设备完整走一遍：查预览、看大屏、下 PDF；
- [ ] 通知老师新学期如何使用、找谁反馈问题。

## 开学第一周

- [ ] 每天看一次运行总览；
- [ ] 收集老师反馈；
- [ ] 处理设备绑定和权限问题；
- [ ] 完成一次数据库备份，作为新学期的基线备份。

## 常见遗留问题

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| 设备显示"未识别班级" | 假期中浏览器数据被清理 | 重新选择班级 |
| 周测日历是空的 | 计划生效日期还是上学期 | 更新计划生效期 |
| 周次对不上 | 学期开始日期没改 | 修改学期开始日期 |
| 域名打不开 | 域名到期或解析被改 | 检查续费和 DNS 记录 |
| 版本检查失败 | 纯内网环境 | 正常降级，不影响核心功能 |
