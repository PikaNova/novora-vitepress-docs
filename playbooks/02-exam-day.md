# 考试当天

大型考试当天最忌讳临时改配置。这篇把当天分成几个时间点，每个点只做该做的事。

## 时间线

```text
考前一天    安排冻结、设备巡检、备份
考前 1 小时  最后确认
开考前      提醒与开考
考试中      暂停/延长等现场调整
结束后      结束、归档、复盘
```

## 考前一天：冻结与巡检

### 冻结安排

- [ ] 确认所有科目时间已经定稿；
- [ ] 确认适用范围正确（尤其别把年级考试误设成全校）；
- [ ] 检查有没有时间重叠冲突；
- [ ] 确认提醒时间点符合这次考试的需要；
- [ ] **从这一刻起不再改时间**，除非确实出错。

### 设备巡检

- [ ] 打开运行总览，确认在线设备数量与预期一致；
- [ ] 逐台确认绑定班级与考场一致；
- [ ] 抽查几台设备，确认显示的是本场考试；
- [ ] 对长期离线的设备现场处理；
- [ ] 提醒设备负责人不要关闭教室电脑、不要清浏览器数据。

### 数据保护

- [ ] 执行一次数据库备份；
- [ ] 导出本场考试的 A4 PDF 备查；
- [ ] 记录当前版本号和提交号。

## 考前 1 小时：最后确认

- [ ] 大屏已经打开并进入全屏；
- [ ] 屏幕上显示的是正确的考试和下一科；
- [ ] 倒计时正常走动；
- [ ] 提醒浮层没有被误关掉；
- [ ] 运行总览没有出现新的冲突或异常提醒；
- [ ] 备用设备（一台笔记本）可以打开同地址。

## 开考前与考试中

### 正常情况

学生开考前 15 分钟和 5 分钟会看到提醒，开考时进入考试状态。这段时间不需要任何操作。

### 需要现场调整时

V2.8.0 起可以在考试记录里直接操作：

| 情况 | 操作 | 注意 |
| --- | --- | --- |
| 实际开考时间需要记录 | 开考 | 记录实际开始时间 |
| 中途需要暂停（例如临时广播） | 暂停 | 暂停时长不计入实际用时 |
| 恢复考试 | 继续 | 自动结算本轮暂停时长 |
| 需要延时 | 延长 | 顺延结束时间，1–600 分钟 |
| 提前结束 | 结束 | 记录实际结束时间 |

每次操作都会留下记录，包含操作人和状态变化，方便事后核对。

### 操作原则

1. **一次只改一件事**，改完确认生效再做下一步；
2. 改完等一分钟，让大屏和插件同步；
3. 不要在开考瞬间改时间——那时候所有设备正在同步；
4. 多人同时操作同一场考试容易冲突，指定一人负责。

## 应急预案

| 情况 | 现场处理 | 兜底方案 |
| --- | --- | --- |
| 某间教室大屏黑屏 | 重开地址、重选班级 | 用 PDF 打印或另一台设备显示 |
| 大屏显示错误班级 | 重新绑定该设备 | 让监考老师口头宣布时间 |
| 时间改了但大屏没变 | 等一分钟；仍不变则刷新设备页面 | 用广播通知 |
| 后台打不开 | 换网络或设备再试 | 用昨天导出的 PDF |
| 系统整体不可用 | 按[回滚流程](/guide/vercel/09-maintenance#更新失败时回滚)处理 | PDF + 广播，考试照常进行 |

::: tip 考试不能因为系统问题停摆
所有应急预案的终点都应该是"考试照常进行"。技术手段只是辅助，现场安排才是主线。
:::

## 考试结束后

- [ ] 确认所有场次都已结束；
- [ ] 记录实际结束时间和异常情况；
- [ ] 把已完成的考试归档（归档后从默认列表隐藏，仍可反归档）；
- [ ] 检查考试记录中的操作记录是否完整；
- [ ] 收集老师反馈；
- [ ] 执行一次数据库备份。

## 复盘要问的四个问题

1. 有没有出现大屏没显示或显示错误的教室？原因是什么？
2. 有没有临时改时间？是因为录入错误还是临时决定？
3. 提醒时间点是否合适？太早还是太晚？
4. 下一次需要提前准备什么？

把结论写下来，下次直接用。
