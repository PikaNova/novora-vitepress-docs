# 第一次全校上线

从"能打开"到"全校正常用"，中间还有一段路。这篇给出一次做完的顺序。

## 时间线总览

```text
上线前 2 周   准备账号、结构、设备
上线前 1 周   录入真实数据、试运行一个年级
上线前 1 天   最终检查、通知
上线当天      逐台确认大屏
上线后 1 周   收集反馈、收尾
```

不建议在正式使用当天才开始部署。DNS 生效、设备调试、老师熟悉都需要时间。

## 上线前 2 周：打好基础

### 系统侧

- [ ] 完成部署并通过[部署验收](/guide/vercel/07-acceptance)（本地部署见[初始化与验收](/guide/local/05-acceptance)）
- [ ] 初始化完成，学校信息正确
- [ ] 年级和班级结构与实际一致
- [ ] 学期开始日期、周次模式、节假日规则已设置
- [ ] 版本为当前稳定版

### 人员侧

- [ ] 确定系统责任人（超级管理员）
- [ ] 确定各年级管理员，并创建账号
- [ ] 确定教室设备负责人（通常电教老师）
- [ ] 明确谁负责更新、谁负责备份

### 基础设施

- [ ] 域名与 HTTPS 正常
- [ ] 学校网络和至少两种手机网络都测过
- [ ] 教室设备能访问正式地址

## 上线前 1 周：先跑一个年级

**只让一个年级真实使用**，比一次性铺开安全得多。

1. 录入这个年级的真实考试安排；
2. 为它的班级创建班级管理员；
3. 逐台设备绑定到实际教室；
4. 让老师用安排预览查一次本班考试；
5. 下载一次 PDF 并打印一张看效果；
6. 收集问题并修复。

这一步能暴露 80% 的问题，而且影响面可控。

## 上线前 1 天：最终检查

- [ ] 所有年级和班级结构最终确认
- [ ] 未来两周的考试安排已录入
- [ ] 每台设备都能打开大屏并显示正确班级
- [ ] 全屏、提醒浮层在真实设备上验证过
- [ ] ClassIsland 插件全部配对完成（如启用）
- [ ] 完成一次数据库备份
- [ ] 恢复密钥位置确认可取用
- [ ] 通知已发给全部使用方

### 通知里要写什么

```text
正式访问地址：
适用范围：
管理员联系渠道：
计划维护时间：
数据录入职责（谁负责录，什么时候截止）：
```

不要公开连接串、环境变量截图、部署钩子或管理员密码。

## 上线当天

1. 早上提前 30 分钟逐台确认大屏；
2. 打开运行总览，确认在线设备数量与预期一致；
3. 处理临时发现的问题；
4. 记录当天所有异常（现象 + 请求 ID）。

## 应急预案

| 情况 | 立刻做什么 | 之后做什么 |
| --- | --- | --- |
| 首页打不开 | 确认是全网还是个别设备；查[故障排查](/appendix/a-troubleshooting) | 记录请求 ID，评估是否回滚 |
| 部分教室大屏异常 | 用另一台设备验证同地址，判断是设备问题还是服务问题 | 现场重开页面或重选班级 |
| 数据没有更新 | 确认后台显示"已保存"；大屏等一分钟再看 | 查[数据同步与离线行为](/features/11-data-sync) |
| 影响范围大且短时间修不好 | 用 PDF 安排作为临时通知手段 | 按[回滚流程](/guide/vercel/09-maintenance#更新失败时回滚)处理 |

::: tip 永远留一条退路
PDF 导出不依赖教室设备，是最可靠的后备通知方式。上线初期建议每天导出一份备查。
:::

## 上线后 1 周

- [ ] 每天看一次运行总览；
- [ ] 收集老师反馈，区分是功能问题还是使用问题；
- [ ] 把常见问题补进校内说明或反馈给作者；
- [ ] 完成第一次定期备份；
- [ ] 确认所有设备绑定稳定，没有频繁上下线；
- [ ] 把操作性经验记录下来，形成校内的小手册。

## 收尾归档

记录以下内容，方便交接和复现：

| 项目 | 内容 |
| --- | --- |
| 上线日期 | |
| 版本号 | 后台「系统设置 → 关于」 |
| 部署方式 | Vercel / Docker / Node |
| 正式地址 | |
| 责任人 | 系统、设备、备份各是谁 |
| 遗留问题 | 现象、请求 ID、临时措施 |
