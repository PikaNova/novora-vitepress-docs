# 1. 超级管理员

超级管理员是系统负责人。除了所有业务模块，还独占角色配置、系统设置、数据维护和版本更新。

## 日常要做的三件事

### 1. 看运行总览

每次登录先花一分钟确认为什么状态：

- 在线设备数与实际情况是否吻合；
- 「需要关注」是否为 0，或所有提醒都已确认；
- 数据库状态是否正常。

发现异常后进入对应模块处理，不要把它当成编辑页面。

### 2. 处理用户与权限

按职责创建账号，而不是按人共享账号：

```text
年级管理员 → 授权到年级
班级管理员 → 一班一账号，授权到班级
班级访客 → 只读范围
```

人员离职或调岗时优先**停用**账号而不是删除，这样审计日志中的历史记录仍有对照。

### 3. 保持版本可用

关注新版本发布说明，在非考试期安排更新。更新流程见对应主线：

- 云端：[Vercel 日常维护](/guide/vercel/09-maintenance)
- 本地：[更新与维护](/guide/local/06-maintenance)

## 学期初

- [ ] 更新学期开始日期和周次模式（统一周表 / A/B 周）
- [ ] 确认节假日排除规则
- [ ] 复核年级与班级结构，处理新高一、毕业年级
- [ ] 复核每个年级管理员的授权范围
- [ ] 复核设备绑定（假期可能挪动过设备）
- [ ] 更新版本到目标稳定版并完成验收
- [ ] 做一次数据库备份并演练恢复
- [ ] 确认恢复密钥仍在受控位置

## 学期末

- [ ] 归档或清理上学期考试记录（V2.8.0 起支持归档状态）
- [ ] 导出需要长期保存的考试与周测 JSON
- [ ] 完成一次离线备份
- [ ] 检查审计日志中的异常操作
- [ ] 停用已离职人员的账号

## 每学期至少一次的安全检查

| 检查项 | 说明 |
| --- | --- |
| 超级管理员数量 | 保持最少必要人数，每人独立账号 |
| 恢复密钥位置 | 确认仍可取用，且未随人员变动丢失 |
| 部署凭据 | 数据库连接串、Deploy Hook、GitHub Token 是否仍受控 |
| 审计日志 | 有无疑似的删除、重置、部署操作 |
| 遥测与错误上报 | 是否符合学校的信息管理要求 |
| 备份可用性 | 最近一次恢复演练是否成功 |

## 只有超级管理员能做的操作

以下操作不对其他角色开放：

- 创建、修改、删除角色；
- 重置年级管理员的密码；
- 系统设置（运行模式、学期、节假日、主题）；
- 数据维护与分模块重置；
- 版本检查与触发部署；
- 使用恢复密钥；
- 初始化补全。

## 高风险操作清单

执行前必须备份，并在非考试时间进行：

1. **数据维护中的模块重置**——按模块清理大型考试、周测、学校结构、设备或调度设置；
2. **删除年级或班级**——会同步清理相关周测计划、班级绑定和旧考试范围；
3. **批量解除设备绑定**——会影响多个教室；
4. **数据库恢复**——可能与当前代码版本不匹配；
5. **版本升级**——跨版本升级前必须先验证。

## 需要留意的默认行为

- 修改 Vercel 的 `ADMIN_PASSWORD` **不会**改变数据库中已有的管理员密码，日常改密要在「用户与权限」中做；
- 重新部署不会修改数据，也不会清空业务数据；
- 一键部署更新只重建当前代码，不负责拉取新版本；
- 停用某个分科目不会删除数据，可以随时重新启用。
